# 避难所：余烬纪元

《避难所：余烬纪元》是对 2023 年猿编程作品的完整重制。正式版本采用 **LayaAir 3.4.0 + TypeScript + Vite** 构建为移动优先 H5 游戏，可直接在桌面或手机浏览器游玩；原 Python/Tkinter 版本保留为迁移行为基线。源码变量和存档字段使用英文，界面、剧情与反馈文案使用中文。

玩家将管理 B-17 避难所，在生存压力下探索 A～H 市、发展设施、招募幸存者，并沿 13 个连续场景揭开“回声菌株”与尸群首领的真相。选择不仅改变资源，也会影响伙伴信任、人性、证据、隐藏线索与最终结局。

## 快速开始

建议使用 Node.js 22 LTS 与项目锁定的 npm 依赖启动 H5 开发服务器；最低兼容范围为 Node.js `^20.19.0 || ^22.13.0 || >=24.0.0`、npm 10 或更高版本。低于该范围时，Vite 8 与 ESLint 10 的构建链会拒绝启动：

```bash
npm ci
npm run dev
```

浏览器访问 `http://127.0.0.1:5173/`。构建和预览生产版本：

```bash
npm run build
npm run preview
```

生产预览地址为 `http://127.0.0.1:4173/`。`npm run build` 会先同步权威配置与封面素材，再执行严格类型检查和 Vite 构建；官方 LayaAir 3.4.0 运行库已固定在 `public/vendor/layaair/3.4.0/`，构建时不会重复下载。

### Python 行为基线

需要比对旧版行为或运行 Python 回归测试时，可使用 Python 3.9 或更高版本：

```bash
python -m pip install -r requirements.txt
python -m apocalypse_game --check
```

Tkinter 界面不再是正式交付入口；只有在需要人工比对旧桌面界面时才需 Tk 8.6 与 Pillow。H5 领域层延续 Python 版已验证的规则，并使用浏览器 `localStorage` 提供版本化存档、滚动备份与 v1 → v2 → v3 → v4 → v5 迁移。

## 封面入口

- `新的游戏`：输入或点选预设所长姓名，开始不含主线任务入口的单人生存战役。
- `游玩存档`：读取本地 JSON 存档；旧版 v1～v4 存档会逐级迁移到 v5 区划远征状态。
- `多人游戏`：两名不同所长在同一台电脑轮流进行生存行动，拥有各自属性和背包，共享避难所、伙伴与设施。
- `剧情模式`：使用单所长独立入口，集中展示主线任务、剧情选择与人物命运。
- `鸣谢`：打开独立鸣谢页；正文按需求保持为空，等待后续文本。
- `更新日志`：右下角灰色独立入口；每次打开网页时自动展示最新版本内容。
- `设置`：封面与局内均有独立入口，系统功能同时可以通过 Escape 菜单访问；完成剧情结局《长夜守望》后，可永久解锁并切换对应主界面封面。

多人模式目前是同一浏览器内的本地轮流合作，不是联网房间。成功的生存行动、剧情结算和经营行动会按规则轮换所长；战斗由双方逐回合交替操作。当前规则中任一所长倒下都会令双人指挥链中断并结束本局，结局文案会明确说明这一点。领域层不依赖 LayaAir，未来可以在现有用例外增加房主权威的网络命令网关。

开始界面使用响应式 2K 正式封面。桌面端使用四态 2K PNG 绘制左侧平行四边形菜单，入口逐项向右下错位；更新日志固定在右下角。鼠标悬停变为橙色，满配置化 300ms 后，简介会跟随指针显示在鼠标下方。手机端使用独立竖版 2K 封面和底部居中的长方形单列，设置键位于左上安全区。封面不提供退出入口，退出只保留在局内 Escape 功能菜单；封面不常驻显示世界观简介、入口小字、图标或页脚。

游戏内界面采用末日指挥台布局：生命、饥饿、基地耐久和群体饥饿使用风险状态条；行动按“核心行动 / 个人保障 / 生存系统”分组。姓名、剧情、战斗、经营、探索、仓库、研发、制作、历史、确认和结局全部是叠加式 LayaAir 页面：下层保留显示，返回只隐藏最上层，不使用浏览器弹窗。所有确定、返回与关闭操作集中在页面底部；Escape 会叠加“存档 / 设置 / 回档 / 退出”功能菜单。桌面保留三栏指挥台，设置与剧情模式入口位于标题栏；真实手机使用居中长方形行动和安全区底栏，普通模式显示“指挥台 / 探索 / 经营 / 物资”四项，剧情模式额外显示“剧情模式”。普通模式只保留人物档案、避难所信息与纯生存内容，不展示剧情任务、剧情战斗或剧情结局；主线任务卡只在剧情模式展示。低于配置化桌面最小宽度的电脑使用保持桌面视觉语言的 `compact` 布局。H5 封面坐标、主题、字体、尺寸、动效、断点、导航位置、模式白名单、行动分组和测试视口均位于 `config/web_config.json`。

## 四章完整主线

主线包含 4 章、13 个连续场景。以下仅介绍章节方向，不揭示关键反转：

| 章节 | 标题 | 核心冲突 |
| --- | --- | --- |
| 第一章 | 饥饿会说话 | 最后一锅粥与神秘广播，把 B-17 引向一列被尸群看守的粮车 |
| 第二章 | 尸群在唱谁的名字 | 伙伴的感染秘密浮出水面，整座城市开始重复一首疏散旋律 |
| 第三章 | 人比末日更会撒谎 | 富足的灯塔避难所邀请众人赴宴，饥荒背后的真相逐渐显现 |
| 第四章 | 余烬之后是什么 | 白塔倒计时启动，玩家必须决定晦城、人类与感染者的未来 |

剧情选择通过资源、属性、设施、伙伴状态、信任、证据、关键物品和 Boss 结果共同解锁。条件不足的选项会显示具体目标、运算符与阈值，例如“食物至少需要 6”；嵌套的“全部 / 任一”条件也会递归展开，而且不会偷偷扣除资源或消耗回合。

### 三场首领战

- `铁轨屠夫·陆沉`：消防外骨骼、月台冲锋与一列不能打开的粮车。
- `鸣钟母体`：声波冲击、群巢点名与持续十八年的疏散广播。
- `无冕王·顾长昼`：牧羊人协议、百万记忆与晦城最后的防火墙。

每场 Boss 都有多条剧情处理路线。路线选择会锁定本次战术；胜利后才原子结算对应效果和 Boss 结果。撤退会保留生存代价与 Boss 剩余生命，但清除未完成路线，允许整备、探索、存读档后重新选择。

战斗提供五项配置化行动：`攻击`、`防御`、`专注`、`使用医疗用品`、`撤退`。攻击、防御、暴击、治疗、撤退概率、Boss 阶段和特殊攻击均来自 `config/story.json`。

重要的时间语义：单个战斗回合不会推进世界时间，也不会重复结算饥饿、避难所损耗或日历。整场战斗胜利后的剧情结算，或成功撤退，才会消耗一次世界行动；战败则直接进入失败结局。战斗中可以保存，Boss 生命、回合、专注和路线都会写入存档。

### 伙伴、信任与隐藏线索

四名主要伙伴分别承担不同玩法职责：

- `豪菜`：基地指挥官与工程师，信任提高后强化设施与白塔工程路线。
- `阳关`：侦察手与共鸣者，能够发现尸群盲区和 Boss 预警。
- `林岚`：医生与病毒学家，强化治疗并降低感染研究风险。
- `小满`：无线电与密码分析员，提高隐藏发现和交易能力。

剧情中的帮助、怀疑、牺牲和背叛会改变伙伴信任及状态。伙伴可能加入、离队、失联或牺牲；这些状态和信任值都会随存档保存。

游戏配置了 10 项发现，包括账本、病历、频率、名单和维护密钥。线索不是单纯收藏品：它们会打开非暴力 Boss 路线、揭示不同真相，并参与秘密结局判定。

### 五种主线结局

主线支持 5 个按条件优先级判定的结局：

- `北行余烬`
- `白塔成灰`
- `静默王冠`
- `长夜守望`
- 秘密结局 `再燃黎明`

最终选择只是结局入口，实际结果还会读取此前的人性、证据、伙伴信任、隐藏线索、避难所状态与三场 Boss 的处理结果。因此，不存在最后一个按钮覆盖整段旅程的情况。

## 生存、探索与避难所经营

完整游戏循环由四条互相影响的路线组成：

```text
城市探索 ──获得食物、药品、金币、零件与随机事件──┐
主线剧情 ──改变伙伴、证据、线索、Boss 与结局条件──┤
避难所管理 ──设施、工作、交易、招募与被动增益────┤
个人行动 ──进食、治疗、分发口粮与修复基地────────┘
                         ↓
             生存消耗、日历推进与失败判定
```

### 基础生存

- 行动时段为 06:00～18:00，日历支持月末、年末和闰年。
- 玩家拥有生命、攻击、防御、敏捷、食物、饥饿、医疗用品、金币、零件与解毒剂等状态。
- 避难所拥有人口、群体饥饿、耐久、防御伤害、活跃度和娱乐物资。
- 个人饥饿、群体饥饿、避难所耐久、玩家生命与活跃度越界都会触发对应失败结局。
- 饥饿已清零、生命或基地耐久已满时，保障行动会直接提示且不扣物资、不推进回合；战斗中满生命也不能浪费医疗用品。
- A～H 市均可探索；银行、医院、商业街、小偷、老人、医疗仓和摩天楼等事件全部由配置驱动。
- 已抽取的探索事件会保存为待结算状态，不能通过保存、读取或重复点击免费重抽，也不能伪造事件 ID。

### 避难所管理

当前经营内容包括：

- 6 项设施：战地厨房、机修工坊、医务室、无线电室、水培温室与复合防御墙。设施有多级成本、即时效果和长期被动修正。
- 5 类工作：整理废料、温室轮班、监听频段、样本研究与外墙巡逻。工作具有配置化成本、区间产出和风险事件。
- 10 项具体交易：不同商人拥有独立解锁条件、数量、买价与卖价。交易不推进世界时间。
- 4 名可招募幸存者：每人拥有条件、成本和避难所增益，成功加入后不能重复招募。

设施建造和工作会严格按配置中的小时数推进日历与对应数量的生存回合，整项计划完成后才轮换所长；交易不推进时间。资源不足或条件未满足时，经营请求不会改变任何状态，也不会消耗世界回合。所有成功操作都先在状态副本上完成校验和结算，再一次性提交。

### 通讯、周档案与十日检查点

- 开始新游戏或读取存档后，先播放“通讯已连接”过场，再进入指挥台。
- 中央通讯栏记录当前周的行动；每 7 个游戏日封存一份周档案、生成周总结，然后清空当前通讯开始新一周。
- `历史记录` 按周展示旧通讯，每条保留生存日、回合、日期和时间。
- 每 10 个游戏日生成一个领域检查点，自动存档仅在新检查点出现时落盘；ESC 菜单中的手动存档始终可用。
- `回档` 只在实际存在十日检查点时启用，成功恢复后会立即持久化，不会退化为普通读档。

### 仓库、研发与制作

- `避难所仓库` 统一展示资源、制作物和剧情关键物品；关键物品是只读档案，不会被误当作可消耗资源。
- 武器和防具可从仓库装备，装备后不再重复计入可用库存，攻击或防御加成由配置与独立服务结算。
- `研究台` 检查前置研发和资源成本；`制作工坊` 使用已解锁配方制作行军口粮、急救包、信标、防护服和步枪。
- 研发和制作均在状态副本上验资、扣料与增加产物，任一前置失败时保持原子性。

### 远征步数与强制返程

- 探索按“城市列表 → 城市需求 → 区划列表 → 区划需求 → 整备”逐级进入，每一级都能返回上一级；携带物在出发时从仓库托管，避免重复使用。
- 八座城市形成 A—H 环形邻接，每市至少六个配置化区划；最大步数由基础值、伙伴词条、信任阈值、已完成研发和携带物加成组成，城市路费与“全局事件成本 + 区划成本”均来自配置。
- 步数足够时可继续深入或随时安全返程；步数不足时强制返回，携带物与战利品合计仅保留 20%，当次领队所长生命直接随机设为配置化的 7～45。
- 多人远征绑定出发所长，即使中途回合轮换，奖励、托管物与生命惩罚也不会错发给其他玩家。

日常无副作用的浏览与菜单操作不会泛化增加饥饿；探索、战斗、设施、工作和修复等真正消耗体力的行动使用 `config/game_config.json` 中的分类饥饿成本。避难所供餐和修复已统一归入“避难所管理 → 生存保障”。

## 存档与 v1 → v2 → v3 → v4 → v5 迁移

当前存档版本是 `schema_version: 5`，默认保存在浏览器 `localStorage` 的配置化键名中，并维护两个滚动备份槽。

v5 在原有玩家、避难所、时间与回合数据之外，完整保存：

- 当前章节、场景、已完成场景、人性、证据、感染压力、标记、关键物品和 Boss 结果；
- 伙伴信任与状态；
- 设施等级；
- 进行中的 Boss 战；
- 已抽取但未结算的探索事件及其城市、区划归属；
- 当前周通讯、按周封存的历史档案和最近十日检查点；
- 制作物仓库、已装备武器/防具与已完成研发；
- 活动远征的领队所长、城市、区划、步数、同行伙伴、托管物和战利品；
- 唯一的结构化结局状态。

读取合法旧存档时，程序按版本依次恢复剧情与设施、时间线与生存系统、开局档案与城市路费，最后通过 `config/save_migrations/v4_to_v5.json` 为当前状态和检查点快照补齐区划。迁移优先选择包含待决事件的区划，没有待决事件时使用城市默认区划。每一版都在迁移前按精确字段结构校验，迁移后再由 v5 严格验证器校验配置 ID、容量、装备分类、城市—区划归属、区划事件池和远征不变量。玩家下一次保存时，主存档会正式写成 v5。

写入新存档前，只会把能够完整解析和校验的旧主档滚动到备份槽。主档损坏时读取层会按新到旧尝试可信备份；未知未来版本、缺失字段或错误类型会被明确拒绝，不会猜测性修补。浏览器禁用持久化时会降级为内存存储，并在界面中提示本次进度仅保留到页面关闭。

## 配置与素材

| 路径 | 职责 |
| --- | --- |
| `config/game_config.json` | 窗口、主题、自绘按钮、行动分组、状态条、初始状态、生存阈值、行动成本和中文界面文案 |
| `config/web_config.json` | LayaAir 版本、舞台缩放、移动断点、安全区、H5 主题、触控尺寸、页面布局、存档键名和 QA 视口 |
| `config/story.json` | 四章主线、伙伴、Boss、战斗、线索、设施、工作、交易、招募与五结局 |
| `config/events.json` | 城市探索事件、选择、权重、随机范围、条件与效果 |
| `config/survival_systems.json` | 仓库目录、装备加成、研发项目、制作配方与远征步数/惩罚 |
| `config/save_migrations/v1_to_v2.json` | 不随新游戏平衡变化的 v1 → v2 存档迁移默认值 |
| `config/save_migrations/v2_to_v3.json` | 版本固定的通讯、仓库、研发、检查点与远征迁移默认值 |
| `config/save_migrations/v3_to_v4.json` | 版本固定的开局档案与城市路费迁移默认值 |
| `config/save_migrations/v4_to_v5.json` | 当前状态与检查点的区划远征迁移版本链 |
| `assets/menu_concept.svg` | 可编辑的主菜单概念图源文件 |
| `assets/menu_concept_2k.png` | 从可编辑源文件导出的 2048×1152 概念图 |
| `assets/cover_art_2k.png` | 游戏运行时使用的 2048×1152 正式封面 |
| `assets/ui/menu_button_*.png` | 桌面封面平行四边形的默认、悬停与按压状态皮肤 |

调整数值、文案、尺寸和断点时优先编辑 JSON，避免把产品规则散落到 TypeScript 或 Python。`npm run sync:assets` 按 `web-assets.json` 把权威配置复制到 Vite 公共目录，避免维护两份剧情数据。Web 配置加载器和领域服务会在启动或首次装配时校验版本、类型、路径和引用；存档再经过独立严格验证器与迁移链。

## 架构分层

```text
LayaAir 页面与组件（src/ui + src/styles）
        ↓ 仅依赖 GameUiPort
展示适配器（src/presentation）
        ↓ 只调用应用用例
GameApplication（src/application）
        ├── StoryService / CombatService / ExplorationService
        ├── ShelterService / InventoryService / EquipmentService
        ├── ResearchCraftingService / ExpeditionService / ChronicleService
        ├── GameRules / StateOperations
        └── GameContent（配置化内容索引）
                    ↓
领域端口（RandomSource / SaveRepository）
                    ↓
浏览器基础设施（localStorage、备份、迁移、验证、随机源）

配置加载与 LayaAir 启动（src/config + src/engine）
                    ↓
组合根（src/main.ts）
```

- `src/domain`：纯领域状态、报告、错误和端口，不依赖 LayaAir 或浏览器。
- `src/services`：剧情、战斗、探索、经营、仓库、装备、研发制作、远征、周档案、时钟、规则与配置化状态操作。
- `src/application`：编排公开用例，并维护“状态副本 → 校验 → 一次提交”的事务边界。
- `src/infrastructure`：浏览器随机源、localStorage、滚动备份、严格校验和 v1 → v2 → v3 → v4 → v5 迁移。
- `src/presentation`：把领域状态投影为只读 UI 快照，把界面命令路由到应用用例。
- `src/ui`：页面栈、响应式页面和可复用 Laya 组件，只依赖 `GameUiPort`。
- `src/config` 与 `src/engine`：严格 Web 配置边界、官方 LayaAir 运行库加载、舞台初始化和前后台限帧。
- `src/main.ts`：唯一组合根，负责依赖装配和可释放生命周期。

该结构遵循 SOLID：页面通过倒置端口访问用例，每个服务保持单一职责，随机数、存档与引擎运行时通过边界注入；增加事件、Boss 或经营内容时优先扩展配置和对应服务，不把分支堆进 Laya 页面回调。

## 长期演进建议

1. 将整数 `negative_status` 升级为带类型、持续时间、叠加规则和每回合效果的 `StatusEffect` 值对象，避免中毒、感染与流血共用同一标量。
2. 把应用层现有的状态副本提交进一步显式化为 `Command → StateDelta → Commit`，为战斗回放、联网同步、审计日志和失败诊断提供稳定协议。
3. 为 `game_config.json`、`story.json` 和 `events.json` 增加正式 JSON Schema，并让编辑器和 CI 在启动前发现目标路径、占位符与条件结构错误。
4. 将现有固定路线战役模拟扩展为多路线 Monte Carlo 门禁，统计普通结局与高风险选择的存活率、资源缺口、伙伴信任分布，并为“故事 / 生存 / 噩梦”难度提供独立配置。
5. 联网多人采用“房主权威状态 + 客户端命令”的模型；网络层只提交版本化领域命令，不直接操作 Laya 显示树或复制领域规则。
6. 把 `GameUiAdapter` 当前读取的 H5 展示配置升级为独立运行时验证器，并为页面端口维护契约测试，降低新增文案字段导致的启动期回归。
7. 将章节插画、伙伴立绘和音频统一接入版本化资源清单与加载策略；领域服务只保存资源键，避免剧情逻辑依赖具体美术文件。
8. 将浏览器尺寸、安全区、方向、Canvas 比例和设备能力继续收敛为可订阅的 `ViewportMetricsPort`，由组合根生成单一快照，减少页面刷新时对 DOM 的重复探测。
