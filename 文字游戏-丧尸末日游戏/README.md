# 避难所·往昔

《避难所·往昔》是对 2023 年猿编程作品的完整重制。项目已收敛为 **LayaAir 3.4.0 + TypeScript + Vite** 的移动优先 H5 游戏，可直接在桌面或手机浏览器游玩。源码变量和存档字段使用英文，界面、剧情与反馈文案使用中文。

玩家将管理 B-17 避难所，在生存压力下探索 A～H 市、发展设施、招募幸存者，并沿 13 个连续场景揭开“回声菌株”与尸群首领的真相。选择不仅改变资源，也会影响伙伴信任、人性、证据、隐藏线索与最终结局。

## 快速开始

建议使用 Node.js 22 LTS 与项目锁定的 npm 依赖启动 H5 开发服务器；最低兼容范围为 Node.js `^20.19.0 || ^22.13.0 || >=24.0.0`、npm 10 或更高版本。低于该范围时，Vite 8 与 ESLint 10 的构建链会拒绝启动：

```bash
npm ci
npm run dev
```

浏览器访问 `http://127.0.0.1:5173/`。构建和预览生产版本：

```bash
npm run build
npm run preview
```

生产预览地址为 `http://127.0.0.1:4173/`。`npm run build` 会先同步权威配置与封面素材，再执行严格类型检查和 Vite 构建；官方 LayaAir 3.4.0 运行库已固定在 `public/vendor/layaair/3.4.0/`，构建时不会重复下载。

游戏使用浏览器 `localStorage` 提供版本化存档、滚动备份与 v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 迁移，不需要安装桌面运行时或额外图形库。

## 封面入口

- `新的游戏`：进入策略式建档，只提供普通求生与无尽求生，并配置所长、难度、起源、特性、城市和栏位；双人与剧情使用各自的独立入口。
- `游玩存档`：读取本地 JSON 存档；旧版 v1～v7 存档会逐级迁移到 v8 生存状态。
- `多人游戏`：两名不同所长在同一台电脑轮流进行生存行动，拥有各自属性和背包，共享避难所、伙伴与设施。
- `剧情模式`：使用单所长独立入口，集中展示主线任务、剧情选择与人物命运。
- `鸣谢`：打开独立鸣谢页；正文按需求保持为空，等待后续文本。
- `更新日志`：右下角灰色独立入口；每次打开网页时自动展示最新版本内容。
- `设置`：封面与局内均有独立入口，系统功能同时可以通过 Escape 菜单访问；完成剧情结局《长夜守望》后，可永久解锁并切换对应主界面封面。

多人模式目前是同一浏览器内的本地轮流合作，不是联网房间。成功的生存行动、剧情结算和经营行动会按规则轮换所长；战斗由双方逐回合交替操作。当前规则中任一所长倒下都会令双人指挥链中断并结束本局，结局文案会明确说明这一点。领域层不依赖 LayaAir，未来可以在现有用例外增加房主权威的网络命令网关。

开始界面使用响应式 2K 正式封面。桌面端使用四态 2K PNG 绘制左侧平行四边形菜单，入口逐项向右下错位；更新日志固定在右下角。鼠标悬停变为橙色，满配置化 300ms 后，简介会跟随指针显示在鼠标下方。手机端使用独立竖版 2K 封面和底部居中的长方形单列，设置键位于左上安全区。封面不提供退出入口，退出只保留在局内 Escape 功能菜单；封面不常驻显示世界观简介、入口小字、图标或页脚。

游戏内界面采用末日指挥台布局：生命、饥饿、基地耐久和群体饥饿使用风险状态条；行动按“生存指令 / 个人保障 / 生存系统”分组。姓名、剧情、战斗、经营、探索、仓库、研发、制作、历史、确认和结局全部是叠加式 LayaAir 页面：下层保留显示，返回只隐藏最上层，不使用浏览器弹窗。所有确定、返回与关闭操作集中在页面底部；Escape 会叠加“存档 / 设置 / 回档 / 退出”功能菜单。桌面保留三栏指挥台，设置与剧情模式入口位于标题栏；真实手机使用居中长方形行动和安全区底栏，普通模式显示“指挥台 / 探索 / 经营 / 物资”四项，剧情模式额外显示“剧情模式”。普通模式只保留人物档案、避难所信息与纯生存内容，不展示剧情任务、剧情战斗或剧情结局；主线任务卡只在剧情模式展示。低于配置化桌面最小宽度的电脑使用保持桌面视觉语言的 `compact` 布局。H5 封面坐标、主题、字体、尺寸、动效、断点、导航位置、模式白名单、行动分组、经营快捷路由和测试视口均位于 `config/web_config.json`。

## v8「地下余烬 Demo」

v8 在原有生存循环和四章主线之外，增加了一组可以独立进入的避难所系统 Demo：4 层 11 个房间的横切面、人员关系规划、3 场手动遭遇战、12 项探索归来事项、8 项避难所活动，以及报纸和书籍各 8 篇的文献存储。它们是现有存档内的可玩功能，不是新增的第五章剧情；剧情 Boss 战仍沿用主线战斗系统，外勤遭遇战则使用独立的前后排小队规则。

### 主要操作路径

- `开局前提示 → 现在查看教程`，或局内 `设置 → 游戏玩法`：打开 14 步指挥官通讯教程。桌面端使用放大的通讯面板并避让当前聚焦目标；手机端正文可拖动或滚动阅读，上一页、下一页和跳过按钮固定在底部。教程只读取当前界面，不推进游戏时间。
- `指挥台 → 避难所地图 → 选择楼层中的房间 → 人员规划`：查看房间人数、容量、运行或封锁状态、设施与区域扩张需求，再将所长和已加入伙伴调入或移出。男、女宿舍分别限制入住性别，人员详情会显示喜欢、讨厌和关系建议。调房不消耗世界回合；当前 Demo 的和谐度用于规划反馈，尚未直接结算生产加成或自动资源惩罚。
- `指挥台 → 外勤遭遇战 → 选择遭遇 → 战前整备 → 开始战斗`：开战前必须为每名单位分配牵制、攻击、游走或救护职责，职责会按配置改变站位与攻防敏属性；可安排消耗医疗用品恢复生命，所有治疗在点击“开始战斗”时原子结算。进入战斗后再逐人选择攻击、防御、技能、道具或撤退，并在需要时指定目标。页面同时显示前后排、生命、技能冷却、战术库存和敌人下一步意图；全员完成指令后才结算敌方阶段。
- `探索 → 完成远征或被强制送回 → 等待所长裁决`：返程完成后按配置概率生成一项待办事项。选择会实时显示资源门槛，确认后原子修改食物、药品、零件、人口、希望、避难所耐久或活动度；未满足要求不会清除事项。待办出现后必须先完成裁决，且不会在已结算的探索回合之外重复增加时间。
- `指挥台 → 文献存储 → 旧报纸或旧书 → 文献标题`：查看当前收集数、已解锁篇数和逐篇目录。每新增一份对应收藏，按配置门槛解锁下一篇正文；锁定项只展示所需数量，已解锁长文支持鼠标滚轮和手机拖动阅读。当前共有 16 篇正文，超过现有目录数量的收藏仍会保留，但不会生成配置外文本。
- `指挥台 → 避难所管理 → 活动`：查看共享晚餐、无线电剧场、防卫演练、厨艺赛和室友协调会等活动的需求、成本与收益，确认后按活动时长推进世界时间。资源或设施条件不足时只显示原因，不提交部分结果。

## 四章完整主线

主线包含 4 章、13 个连续场景。以下仅介绍章节方向，不揭示关键反转：

| 章节 | 标题 | 核心冲突 |
| --- | --- | --- |
| 第一章 | 饥饿会说话 | 最后一锅粥与神秘广播，把 B-17 引向一列被尸群看守的粮车 |
| 第二章 | 尸群在唱谁的名字 | 伙伴的感染秘密浮出水面，整座城市开始重复一首疏散旋律 |
| 第三章 | 人比末日更会撒谎 | 富足的灯塔避难所邀请众人赴宴，饥荒背后的真相逐渐显现 |
| 第四章 | 余烬之后是什么 | 白塔倒计时启动，玩家必须决定晦城、人类与感染者的未来 |

剧情选择通过资源、属性、设施、伙伴状态、信任、证据、关键物品和 Boss 结果共同解锁。条件不足的选项会显示具体目标、运算符与阈值，例如“食物至少需要 6”；嵌套的“全部 / 任一”条件也会递归展开，而且不会偷偷扣除资源或消耗回合。

### 三场首领战

- `铁轨屠夫·陆沉`：消防外骨骼、月台冲锋与一列不能打开的粮车。
- `鸣钟母体`：声波冲击、群巢点名与持续十八年的疏散广播。
- `无冕王·顾长昼`：牧羊人协议、百万记忆与晦城最后的防火墙。

每场 Boss 都有多条剧情处理路线。路线选择会锁定本次战术；胜利后才原子结算对应效果和 Boss 结果。撤退会保留生存代价与 Boss 剩余生命，但清除未完成路线，允许整备、探索、存读档后重新选择。

战斗提供五项配置化行动：`攻击`、`防御`、`专注`、`使用医疗用品`、`撤退`。攻击、防御、暴击、治疗、撤退概率、Boss 阶段和特殊攻击均来自 `config/story.json`。

重要的时间语义：单个战斗回合不会推进世界时间，也不会重复结算饥饿、避难所损耗或日历。整场战斗胜利后的剧情结算，或成功撤退，才会消耗一次世界行动；战败则直接进入失败结局。战斗中可以保存，Boss 生命、回合、专注和路线都会写入存档。

### 伙伴、信任与隐藏线索

四名主要伙伴分别承担不同玩法职责：

- `豪菜`：基地指挥官与工程师，信任提高后强化设施与白塔工程路线。
- `阳关`：侦察手与共鸣者，能够发现尸群盲区和 Boss 预警。
- `林岚`：医生与病毒学家，强化治疗并降低感染研究风险。
- `小满`：无线电与密码分析员，提高隐藏发现和交易能力。

剧情中的帮助、怀疑、牺牲和背叛会改变伙伴信任及状态。伙伴可能加入、离队、失联或牺牲；这些状态和信任值都会随存档保存。

游戏配置了 10 项发现，包括账本、病历、频率、名单和维护密钥。线索不是单纯收藏品：它们会打开非暴力 Boss 路线、揭示不同真相，并参与秘密结局判定。

### 五种主线结局

主线支持 5 个按条件优先级判定的结局：

- `北行余烬`
- `白塔成灰`
- `静默王冠`
- `长夜守望`
- 秘密结局 `再燃黎明`

最终选择只是结局入口，实际结果还会读取此前的人性、证据、伙伴信任、隐藏线索、避难所状态与三场 Boss 的处理结果。因此，不存在最后一个按钮覆盖整段旅程的情况。

## 生存、探索与避难所经营

完整游戏循环由四条互相影响的路线组成：

```text
城市探索 ──获得食物、药品、金币、零件与随机事件──┐
主线剧情 ──改变伙伴、证据、线索、Boss 与结局条件──┤
避难所管理 ──设施、工作、交易、招募与被动增益────┤
个人行动 ──进食、治疗、分发口粮与修复基地────────┘
                         ↓
             生存消耗、日历推进与失败判定
```

### 基础生存

- 行动时段为 06:00～18:00，日历支持月末、年末和闰年。
- 玩家拥有生命、攻击、防御、敏捷、食物、饥饿、医疗用品、金币、零件与解毒剂等状态。
- 避难所拥有人口、群体饥饿、耐久、防御伤害、活跃度、希望值和娱乐物资。
- 所长拥有年龄与每局随机生成的 70～120 岁寿命；个人饥饿、群体饥饿、避难所耐久、生命、活跃度、希望值或寿命越界都会触发对应失败结局。
- 饥饿已清零、生命或基地耐久已满时，保障行动会直接提示且不扣物资、不推进回合；战斗中满生命也不能浪费医疗用品。
- A～H 市均可探索；银行、医院、商业街、小偷、老人、医疗仓和摩天楼等事件全部由配置驱动。
- 已抽取的探索事件会保存为待结算状态，不能通过保存、读取或重复点击免费重抽，也不能伪造事件 ID。

### 避难所管理

当前经营内容包括：

- 避难所管理分为“经营 / 活动 / 升级”三类；指挥台“设施管理”使用 `config/web_config.json` 的快捷路由打开升级页，不在 TypeScript 中硬编码分类 ID。
- 9 项设施：6 项原有生产与防御设施，加上区域扩张、水净化中心与能源中心。初始区域的常规设施总等级上限为 10；区域扩张逐级提高容量，并解锁后续新设施。尚未扩张时，受限设施保持灰色，点入或悬停均会显示需求与功能简介。
- 5 类工作：整理废料、温室轮班、监听频段、样本研究与外墙巡逻。工作具有配置化成本、区间产出和风险事件。
- 10 项具体交易：不同商人拥有独立解锁条件、数量、买价与卖价。买入与卖出共享“每个生存周一次”额度；贸易不推进世界时间，但运输途中可能被抢，并进入配置化的追踪、反击、赔偿、伤害或失散结果。
- 4 名可招募幸存者：每人拥有条件、成本和避难所增益，成功加入后不能重复招募。
- 独立的避难所活动分类：每项活动先展示需求与收益，确认后只结算一次，并影响希望、活跃度或资源。

设施建造和工作会严格按配置中的小时数推进日历与对应数量的生存回合，整项计划完成后才轮换所长；交易不推进时间，每周额度和途中被抢结果会作为同一次原子结算。资源不足、区域未扩张或条件未满足时，经营请求不会改变任何状态，也不会消耗世界回合。所有成功操作都先在状态副本上完成校验和结算，再一次性提交。

### 通讯、周档案与十日检查点

- 开始新游戏或读取存档后，先播放“通讯已连接”过场，再进入指挥台。
- 中央通讯栏记录当前周的行动；每 7 个游戏日封存一份周档案、生成周总结，然后清空当前通讯开始新一周。
- `历史记录` 按周展示旧通讯，每条保留生存日、回合、日期和时间。
- 每 10 个游戏日生成一个领域检查点，自动存档仅在新检查点出现时落盘；ESC 菜单中的手动存档始终可用。
- `回档` 只在实际存在十日检查点时启用，成功恢复后会立即持久化，不会退化为普通读档。

### 仓库、研发与制作

- `避难所仓库` 统一展示资源、制作物和剧情关键物品；关键物品是只读档案，不会被误当作可消耗资源。
- 武器和防具可从仓库装备，装备后不再重复计入可用库存，攻击或防御加成由配置与独立服务结算。
- 载具使用独立的“载具设置”页，最多同时装备两辆；仅放在仓库中不代表可驾驶，已装备载具也不再重复计入可用数量。陆地、海上与飞行类型由 `config/survival_systems.json` 配置。
- `研究台` 检查前置研发和资源成本；`制作工坊` 使用已解锁配方制作行军口粮、急救包、信标、防护服和步枪。
- 研发和制作均在状态副本上验资、扣料与增加产物，任一前置失败时保持原子性。

### 携带食物、区划选项与强制返程

- 探索按“城市列表 → 城市需求 → 区划列表 → 区划需求 → 多层行动选项 → 整备”逐级进入，每一级都能返回上一级；携带物在出发时从仓库托管，避免重复使用。
- 每个真实区划按需生成 `40 → 20 → 10 → 10` 的四层结构，部分区划再追加第五层 10 个选项。配置只保存分支数量和可替换占位模板，服务根据稳定路径即时生成当前层，不会在内存或包体中展开数亿节点；正式文本以后可按稳定节点 ID 覆盖。
- A～G 市使用双向相邻链，H 市是没有附近城市的孤岛；每市至少六个配置化区划。H 市禁止路线图绕行，必须同时装备海上载具和飞行载具；其他远城也只认可已装备的适配载具。
- 每携带 1 份食物可支撑 1 次移动或探索行动，城市路程与区划事件会真实扣除携带食物。伙伴、特性、研发与非食物道具不再凭空增加行动次数；食物不足时强制返回，携带物与战利品合计仅保留 20%，当次领队所长生命随机降至配置化的 7～45。
- 多人远征绑定出发所长，即使中途回合轮换，奖励、托管物与生命惩罚也不会错发给其他玩家。

日常无副作用的浏览与菜单操作不会泛化增加饥饿；探索、战斗、设施、工作和修复等真正消耗体力的行动使用 `config/game_config.json` 中的分类饥饿成本。避难所供餐和修复已统一归入“避难所管理 → 生存保障”。

## 存档与 v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 迁移

当前存档版本是 `schema_version: 8`，默认保存在浏览器 `localStorage` 的配置化键名中，并维护两个滚动备份槽。

v8 在原有玩家、避难所、时间与回合数据之外，完整保存：

- 当前章节、场景、已完成场景、人性、证据、感染压力、标记、关键物品和 Boss 结果；
- 伙伴信任与状态；
- 设施等级；
- 进行中的 Boss 战；
- 已抽取但未结算的探索事件及其城市、区划归属；
- 当前周通讯、按周封存的历史档案和最近十日检查点；
- 制作物仓库、已装备武器/防具与已完成研发；
- 活动远征的领队所长、城市、区划、食物行动余额、同行伙伴、托管物和战利品；旧字段名只作为 v1～v8 兼容载体保留；
- 所长年龄、随机寿命、避难所希望值、伙伴配装/互动冷却、活动状态与结构化远征失败结算；
- 已装备的陆地、海上或飞行载具，以及载具占用后的可用库存不变式；
- 区域扩张与新设施等级，以及“每个生存周一次”的经营周期使用记录；
- 避难所各房间的人员安排、进行中的手动遭遇战完整快照，以及尚未裁决的归来事项稳定 ID；
- 唯一的结构化结局状态。

读取合法旧存档时，程序按版本依次恢复剧情与设施、时间线与生存系统、开局档案与城市路费、区划远征状态，再通过 `config/save_migrations/v5_to_v6.json` 补齐寿命、希望、伙伴管理及失败结算字段，通过 `config/save_migrations/v6_to_v7.json` 补齐载具装备、新设施和经营周期记录，最后由 `config/save_migrations/v7_to_v8.json` 为当前状态与检查点补齐房间安排、手动遭遇战和归来事项字段。每一版都在迁移前按精确字段结构校验，迁移后再由 v8 严格验证器校验配置 ID、容量、装备分类与占用、经营周期、城市—区划归属、区划事件池、房间分配的跨房间唯一性、遭遇战生命/站位/顺序/冷却/补给结构和远征不变量。玩家下一次保存时，主存档会正式写成 v8。

写入新存档前，只会把能够完整解析和校验的旧主档滚动到备份槽。主档损坏时读取层会按新到旧尝试可信备份；未知未来版本、缺失字段或错误类型会被明确拒绝，不会猜测性修补。浏览器禁用持久化时会降级为内存存储，并在界面中提示本次进度仅保留到页面关闭。

## 架构分层

```text
LayaAir 页面与组件（src/ui + src/styles）
        ↓ 仅依赖 GameUiPort
展示适配器（src/presentation）
        ↓ 只调用应用用例
GameApplication（src/application）
        ├── StoryService / CombatService / ExplorationService
        ├── ShelterService / InventoryService / EquipmentService
        ├── ShelterLayoutService / DemoSystemsCoordinator
        ├── EncounterBattleService / ReturnIncidentService / ArchiveStorageService
        ├── TradeAmbushService / TransportLoadoutService
        ├── CompanionManagementService / CampaignProfileService
        ├── ResearchCraftingService / ExpeditionService / ChronicleService
        ├── GameRules / StateOperations
        └── GameContent（配置化内容索引）
                    ↓
领域端口（RandomSource / SaveRepository）
                    ↓
浏览器基础设施（localStorage、备份、迁移、验证、随机源）

配置加载与 LayaAir 启动（src/config + src/engine）
                    ↓
组合根（src/main.ts）
```

- `src/domain`：纯领域状态、报告、错误和端口，不依赖 LayaAir 或浏览器。
- `src/services`：剧情、Boss 战、探索、经营、避难所横切面、手动遭遇战、归来事项、文献存储、仓库、装备、载具配装、贸易途中被抢、研发制作、远征、周档案、时钟、规则与配置化状态操作；`DemoSystemsCoordinator` 只编排三个独立 Demo 服务，不把领域结算塞入 UI。
- `src/application`：编排公开用例，并维护“状态副本 → 校验 → 一次提交”的事务边界。
- `src/infrastructure`：浏览器随机源、localStorage、滚动备份、严格校验和 v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 迁移。
- `src/presentation`：把领域状态投影为只读 UI 快照，把界面命令路由到应用用例。
- `src/ui`：页面栈、响应式页面和可复用 Laya 组件，只依赖 `GameUiPort`。
- `src/config` 与 `src/engine`：严格 Web 配置边界、官方 LayaAir 运行库加载、舞台初始化和前后台限帧。
- `src/main.ts`：唯一组合根，负责依赖装配和可释放生命周期。

该结构遵循 SOLID：页面通过倒置端口访问用例，每个服务保持单一职责，随机数、存档与引擎运行时通过边界注入；增加事件、Boss 或经营内容时优先扩展配置和对应服务，不把分支堆进 Laya 页面回调。

## 测试与验证

H5 完整门禁：

```bash
npm run check
npm run test:e2e
```

当前工作树的测试基线为：

- `npm run test`：运行 40 个 Vitest 文件、337 个测试，再运行 3 个 Node 素材策略测试。
- `npm run test:e2e -- --list`：列出 18 条真实 Canvas 流程在 10 个 Playwright 视口项目中的 180 个执行用例；去掉 `--list` 才会实际启动浏览器执行。

Playwright 视口来自 `config/web_config.json`，包括桌面、多个手机、横屏、平板、窄桌面、矮桌面与超宽屏。当前 18 条端到端流程覆盖建档、教程、剧情入口、六栏存档、叠加菜单、多层区划远征、归来事项、遭遇战职责与手动指令、活动和响应式交互；避难所地图规划和文献阅读的更多边界目前仍由领域、应用与页面级 Vitest 覆盖。

## 长期演进建议

1. 将整数 `negative_status` 升级为带类型、持续时间、叠加规则和每回合效果的 `StatusEffect` 值对象，避免中毒、感染与流血共用同一标量。
2. 把应用层现有的状态副本提交进一步显式化为 `Command → StateDelta → Commit`，为战斗回放、联网同步、审计日志和失败诊断提供稳定协议。
3. 为 `game_config.json`、`story.json` 和 `events.json` 增加正式 JSON Schema，并引入独立 `StoryConfigValidator`，将设施扩张目标、贸易周期键、抢劫分支和跨文档 ID 引用校验从服务构造器中移出，让编辑器与 CI 在启动前就能失败。
4. 将现有固定路线战役模拟扩展为多路线 Monte Carlo 门禁，统计普通结局与高风险选择的存活率、资源缺口、伙伴信任分布，并为“故事 / 生存 / 噩梦”难度提供独立配置。
5. 联网多人采用“房主权威状态 + 客户端命令”的模型；网络层只提交版本化领域命令，不直接操作 Laya 显示树或复制领域规则。
6. 把 `GameUiAdapter` 当前读取的 H5 展示配置升级为独立运行时验证器，并为页面端口维护契约测试，降低新增文案字段导致的启动期回归。
7. 将章节插画、伙伴立绘和音频统一接入版本化资源清单与加载策略；领域服务只保存资源键，避免剧情逻辑依赖具体美术文件。
8. 将浏览器尺寸、安全区、方向、Canvas 比例和设备能力继续收敛为可订阅的 `ViewportMetricsPort`，由组合根生成单一快照，减少页面刷新时对 DOM 的重复探测。
9. 按风险递增顺序拆分超大界面类：先用 `WebShellPlatformPort` 移出浏览器返回、视口与退出策略；再将 `GameShell` 中的伙伴、远征和系统菜单编排分别收敛到 `CompanionFlowController`、`ExpeditionFlowController` 和 `SystemMenuFlowController`。
10. 将建档状态从 `NewGameSetupPage` 抽成不依赖 Laya 的 `NewGameSetupStore`，由桌面与手机渲染器共享姓名、模式、起源、特性和栏位校验；职责稳定后再引入快照切片与增量渲染，避免手机每次状态变化都重建整棵显示树。
11. 在把房间和谐度接入生产、希望或随机事项前，先引入独立的 `ShelterEffectProjection` 与配置化公式；伙伴战斗属性也应由专用档案或装备端口提供，避免横切面展示规则、角色成长和遭遇战数值在协调器中互相耦合。
12. v9 存档迁移时将兼容字段 `remaining_steps`、`maximum_steps` 和 `steps_exhausted` 正式重命名为食物行动语义，并删除不再参与行动额度的伙伴/研发步数投影；迁移前继续保持 v1～v8 精确读档。
13. 当前主包超过 500 KB 警戒线。优先按页面流拆分文献正文、避难所地图、区划探索树和战斗 UI，并让 `GameShell` 只加载当前路由控制器；用构建预算测试防止新增内容再次回流主包。
