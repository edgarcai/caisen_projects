# 避难所：余烬纪元

《避难所：余烬纪元》是对 2023 年猿编程作品的标准 Python 完整重制。项目已移除 `ybc_ui` 与 `cosplay`，可以在普通 Python 环境运行；源码变量和存档字段使用英文，界面、剧情与反馈文案使用中文。

玩家将管理 B-17 避难所，在生存压力下探索 A～H 市、发展设施、招募幸存者，并沿 13 个连续场景揭开“回声菌株”与尸群首领的真相。选择不仅改变资源，也会影响伙伴信任、人性、证据、隐藏线索与最终结局。

## 快速开始

建议使用 Python 3.9 或更高版本，并确认 Python 绑定 Tk 8.6 或更高版本：

```bash
cd "文字游戏-丧尸末日游戏"
python -m pip install -r requirements.txt
python main.py
```

也可以使用包入口：

```bash
python -m apocalypse_game
```

启动前可检查 Python 与 Tk 版本：

```bash
python -c "import sys, tkinter; print(sys.version); print('Tk', tkinter.TkVersion)"
```

macOS 自带的 `/usr/bin/python3` 可能仍绑定 Tk 8.5，无法运行本项目界面。请改用带 Tk 8.6 的 Conda、python.org 或其他可信 Python 发行版。部分精简版 Python 未包含 Tkinter，也需要更换或补装带 Tk 支持的 Python。

Pillow 用于稳定加载和缩放概念图；图片或 Pillow 不可用时，程序会切换到低资源背景，不影响领域玩法。

无窗口启动自检：

```bash
python -m apocalypse_game --check
```

## 三种主菜单入口

- `新的游戏`：输入一名所长姓名，开始单人完整战役。
- `游玩存档`：读取本地 JSON 存档；旧版 v1 存档会在读取时迁移到 v2 领域状态。
- `多人游戏`：两名不同所长在同一台电脑轮流行动，拥有各自属性和背包，共享避难所、剧情、伙伴与设施。

多人模式目前是本地轮流合作，不是联网房间。成功的生存行动、剧情结算和经营行动会按规则轮换所长；战斗由双方逐回合交替操作。领域层不依赖 Tkinter，未来可以在现有用例外增加房主权威的网络命令网关。

游戏内界面采用末日指挥台布局：生命、饥饿、基地耐久和群体饥饿使用风险状态条；行动按“核心行动 / 基地保障 / 系统指令”分组，并提供图标、副标题、悬停、按压、焦点与禁用反馈。按钮由 Canvas 自绘，不依赖 macOS Aqua、Windows 或 Linux 的原生按钮配色，因此不会出现浅色系统按钮配白色文字的问题。按钮色、尺寸、行动分组、图标、提示文案和状态条阈值均位于 `config/game_config.json`，无需修改 Python 即可调整。

## 四章完整主线

主线包含 4 章、13 个连续场景。以下仅介绍章节方向，不揭示关键反转：

| 章节 | 标题 | 核心冲突 |
| --- | --- | --- |
| 第一章 | 饥饿会说话 | 最后一锅粥与神秘广播，把 B-17 引向一列被尸群看守的粮车 |
| 第二章 | 尸群在唱谁的名字 | 伙伴的感染秘密浮出水面，整座城市开始重复一首疏散旋律 |
| 第三章 | 人比末日更会撒谎 | 富足的灯塔避难所邀请众人赴宴，饥荒背后的真相逐渐显现 |
| 第四章 | 余烬之后是什么 | 白塔倒计时启动，玩家必须决定晦城、人类与感染者的未来 |

剧情选择通过资源、属性、设施、伙伴状态、信任、证据、关键物品和 Boss 结果共同解锁。条件不足的选项会显示为锁定，不会偷偷扣除资源或消耗回合。

### 三场首领战

- `铁轨屠夫·陆沉`：消防外骨骼、月台冲锋与一列不能打开的粮车。
- `鸣钟母体`：声波冲击、群巢点名与持续十八年的疏散广播。
- `无冕王·顾长昼`：牧羊人协议、百万记忆与晦城最后的防火墙。

每场 Boss 都有多条剧情处理路线。路线选择会锁定本次战术；胜利后才原子结算对应效果和 Boss 结果。撤退会保留生存代价，但清除未完成路线，允许整备后重新选择。

战斗提供五项配置化行动：`攻击`、`防御`、`专注`、`使用医疗用品`、`撤退`。攻击、防御、暴击、治疗、撤退概率、Boss 阶段和特殊攻击均来自 `config/story.json`。

重要的时间语义：单个战斗回合不会推进世界时间，也不会重复结算饥饿、避难所损耗或日历。整场战斗胜利后的剧情结算，或成功撤退，才会消耗一次世界行动；战败则直接进入失败结局。战斗中可以保存，Boss 生命、回合、专注和路线都会写入存档。

### 伙伴、信任与隐藏线索

四名主要伙伴分别承担不同玩法职责：

- `豪菜`：基地指挥官与工程师，信任提高后强化设施与白塔工程路线。
- `阳关`：侦察手与共鸣者，能够发现尸群盲区和 Boss 预警。
- `林岚`：医生与病毒学家，强化治疗并降低感染研究风险。
- `小满`：无线电与密码分析员，提高隐藏发现和交易能力。

剧情中的帮助、怀疑、牺牲和背叛会改变伙伴信任及状态。伙伴可能加入、离队、失联或牺牲；这些状态和信任值都会随存档保存。

游戏配置了 10 项发现，包括账本、病历、频率、名单和维护密钥。线索不是单纯收藏品：它们会打开非暴力 Boss 路线、揭示不同真相，并参与秘密结局判定。

### 五种主线结局

主线支持 5 个按条件优先级判定的结局：

- `北行余烬`
- `白塔成灰`
- `静默王冠`
- `长夜守望`
- 秘密结局 `再燃黎明`

最终选择只是结局入口，实际结果还会读取此前的人性、证据、伙伴信任、隐藏线索、避难所状态与三场 Boss 的处理结果。因此，不存在最后一个按钮覆盖整段旅程的情况。

## 生存、探索与避难所经营

完整游戏循环由四条互相影响的路线组成：

```text
城市探索 ──获得食物、药品、金币、零件与随机事件──┐
主线剧情 ──改变伙伴、证据、线索、Boss 与结局条件──┤
避难所管理 ──设施、工作、交易、招募与被动增益────┤
个人行动 ──进食、治疗、分发口粮与修复基地────────┘
                         ↓
             生存消耗、日历推进与失败判定
```

### 基础生存

- 行动时段为 06:00～18:00，日历支持月末、年末和闰年。
- 玩家拥有生命、攻击、防御、敏捷、食物、饥饿、医疗用品、金币、零件与解毒剂等状态。
- 避难所拥有人口、群体饥饿、耐久、防御伤害、活跃度和娱乐物资。
- 个人饥饿、群体饥饿、避难所耐久、玩家生命与活跃度越界都会触发对应失败结局。
- A～H 市均可探索；银行、医院、商业街、小偷、老人、医疗仓和摩天楼等事件全部由配置驱动。
- 已抽取的探索事件会保存为待结算状态，不能通过保存、读取或重复点击免费重抽，也不能伪造事件 ID。

### 避难所管理

当前经营内容包括：

- 6 项设施：战地厨房、机修工坊、医务室、无线电室、水培温室与复合防御墙。设施有多级成本、即时效果和长期被动修正。
- 5 类工作：整理废料、温室轮班、监听频段、样本研究与外墙巡逻。工作具有配置化成本、区间产出和风险事件。
- 10 项具体交易：不同商人拥有独立解锁条件、数量、买价与卖价。交易不推进世界时间。
- 4 名可招募幸存者：每人拥有条件、成本和避难所增益，成功加入后不能重复招募。

设施建造和工作会严格按配置中的小时数推进日历与对应数量的生存回合，整项计划完成后才轮换所长；交易不推进时间。资源不足或条件未满足时，经营请求不会改变任何状态，也不会消耗世界回合。所有成功操作都先在状态副本上完成校验和结算，再一次性提交。

## 存档与 v1 → v2 迁移

当前存档版本是 `schema_version: 2`，默认路径为 `saves/savegame.json`。

v2 在原有玩家、避难所、时间与回合数据之外，完整保存：

- 当前章节、场景、已完成场景、人性、证据、感染压力、标记、关键物品和 Boss 结果；
- 伙伴信任与状态；
- 设施等级；
- 进行中的 Boss 战；
- 已抽取但未结算的探索事件；
- 唯一的结构化结局状态。

读取合法 v1 存档时，程序会先按 v1 的精确字段结构校验，再通过 `config/save_migrations/v1_to_v2.json` 在内存中迁移：原有生存资源、时间和回合全部保留，同时补入版本固定的剧情、伙伴和设施默认值。已经结束的 v1 游戏会映射为 `legacy_failure`，保留原结局文案。玩家下一次保存时，主存档会正式写成 v2。

存档写入使用同目录临时文件、磁盘同步和原子替换；覆盖有效主档前会保留最近一次 `savegame.bak`。主档损坏时读取层会尝试可信备份。未知的未来存档版本、缺失字段或错误类型会被明确拒绝，不会猜测性修补。

## 配置与素材

| 路径 | 职责 |
| --- | --- |
| `config/game_config.json` | 窗口、主题、自绘按钮、行动分组、状态条、初始状态、生存阈值、行动成本和中文界面文案 |
| `config/story.json` | 四章主线、伙伴、Boss、战斗、线索、设施、工作、交易、招募与五结局 |
| `config/events.json` | 城市探索事件、选择、权重、随机范围、条件与效果 |
| `config/save_migrations/v1_to_v2.json` | 不随新游戏平衡变化的 v1 → v2 存档迁移默认值 |
| `assets/menu_concept.svg` | 可编辑的主菜单概念图源文件 |
| `assets/menu_concept.png` | 游戏运行时使用的 1280×720 概念图 |

调整数值时优先编辑 JSON，避免把平衡值散落到 Python 代码。配置加载器会校验路径边界、唯一 ID、场景引用、Boss 引用、选择数量、存档版本、状态目标、随机区间、交易与设施结构。

## 架构分层

```text
Tkinter UI（ui.py）
        ↓ 只调用公开用例
GameApplication（application.py）
        ├── StoryService（主线、条件、伙伴、线索、结局）
        ├── CombatService（回合、Boss 阶段、胜负与撤退）
        ├── ShelterService（设施、工作、交易、招募、被动修正）
        ├── ExplorationEventService（城市随机事件）
        ├── GameRules（生存消耗、时间、不变量、失败结局）
        └── StateOperations（配置化目标白名单与原子数值效果）
                    ↓
Ports（SaveRepository / RandomSource）
                    ↓
Infrastructure（JSON 存档、v1→v2 迁移、备份、随机源）
```

- `domain.py`：玩家、避难所、剧情、伙伴、战斗、待探索、结局、时钟和不可变报告等纯领域状态。
- `application.py`：编排主线、战斗、探索、经营、物品、保存与读取，并维护状态副本的提交边界。
- `story.py`：稳定场景图、递归条件、伙伴同步、隐藏发现和多结局优先级。
- `combat.py`：五类战斗行动、Boss 阶段、伤害与撤退结算。
- `shelter.py`：经营选项查询、设施升级、工作、买卖、招募和被动增益。
- `events.py`：配置驱动的随机探索准备与原子结算。
- `rules.py`：世界时间、生存消耗、状态钳制和失败优先级。
- `state_ops.py`：统一读取和修改允许暴露给配置的英文状态目标。
- `ports.py`：存档仓库与随机源的最小接口。
- `infrastructure.py`：版本化 JSON、迁移链、严格校验、原子写入与备份恢复。
- `config.py`：主配置、剧情配置和事件配置的启动期深层校验。
- `bootstrap.py`：唯一依赖组装入口。
- `ui.py`：中文展示和输入，不直接修改领域状态。
- `widgets.py`：跨平台自绘按钮与资源状态条，隔离 Tk 原生主题差异。

该结构遵循 SOLID：界面依赖应用用例，应用依赖职责单一的领域服务，随机数和存档通过接口注入；增加事件、Boss 或经营内容时，优先扩展配置和对应服务，不把分支重新堆回 Tkinter 回调。

## 长期演进建议

1. 将整数 `negative_status` 升级为带类型、持续时间、叠加规则和每回合效果的 `StatusEffect` 值对象，避免中毒、感染与流血共用同一标量。
2. 把应用层现有的状态副本提交进一步显式化为 `Command → StateDelta → Commit`，为战斗回放、联网同步、审计日志和失败诊断提供稳定协议。
3. 为 `game_config.json`、`story.json` 和 `events.json` 增加正式 JSON Schema，并让编辑器和 CI 在启动前发现目标路径、占位符与条件结构错误。
4. 将现有固定路线战役模拟扩展为多路线 Monte Carlo 门禁，统计普通结局与高风险选择的存活率、资源缺口、伙伴信任分布，并为“故事 / 生存 / 噩梦”难度提供独立配置。
5. 联网多人采用“房主权威状态 + 客户端命令”的模型；网络线程通过命令队列通知主线程，不直接操作 Tk 控件或复制领域规则。
